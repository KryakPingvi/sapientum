# Проверка в браузере

Запусти Docker Desktop. Из корня проекта:

```powershell
npm ci
npm run dev
```

Открой **http://127.0.0.1:3000**. Остановка сервера — Ctrl+C. Если порт 3000 занят, освободи его перед запуском. Используй именно `127.0.0.1`: хост и Origin проверяются строго.

Команда собирает модули, поднимает отдельный PostgreSQL на порту 55433, применяет миграции и создаёт демотурнир и аккаунты. Обычная тестовая база на 5432 не используется.

| Логин       | Пароль      | Роль                        |
| ----------- | ----------- | --------------------------- |
| `organizer` | `demo12345` | Администратор и организатор |
| `leader`    | `demo12345` | Руководитель команды        |
| `jury`      | `demo12345` | Жюри                        |

## Что проверить

1. Войди под `leader`. Введи название, организацию и ФИО, нажми «Подать заявку». Команда появится со статусом `pending`.
2. Попробуй подтвердить её под `leader`: получишь 403 `FORBIDDEN`.
3. Войди под `organizer`, подтверди команду: статус станет `confirmed`. Проверь фильтры списков.
4. Под организатором закрой регистрацию. Под руководителем попробуй подать новую заявку: будет 409 `REGISTRATION_CLOSED`. Верни открытую регистрацию.
5. Загрузи оргкомитет под организатором, сними у него `organizer`, оставив `administrator`, и сохрани. Подтверждение другой неподтверждённой команды теперь вернёт 403. Верни флаг. Снять последнего администратора система не разрешит.
6. Войди одним аккаунтом в обычном окне и инкогнито с разными названиями устройств. В «Мои сессии» закрой сессию другого окна. Следующее защищённое действие там получит 401; другая сессия продолжит работать. Публичный список команд остаётся доступен.
7. «Выйти на всех устройствах» закрывает все сессии текущего аккаунта.

Обычные вкладки одного профиля делят refresh-cookie. Для независимых устройств используй инкогнито, другой профиль или другой браузер на этом компьютере. Перезагрузка страницы сбрасывает access-токен из памяти: нажми «Обновить токен», чтобы восстановить вход через refresh-cookie.

Результат действия и HTTP-статус видны внизу. Через F12 → Network можно смотреть запросы. Это ручная проверка настоящих HTTP-адаптеров и PostgreSQL, не имитация ответов.

## Данные и повторный запуск

Снова выполни `npm run dev`. Команды, роли и сессии сохраняются между запусками. Ключ JWT создаётся при каждом старте: после перезапуска войди заново или нажми «Обновить токен».

При работающем сервере `npm run dev:check` проверяет вход, заявки, подтверждение, права и отзыв сессии по HTTP. Проверка оставляет команду `HTTP ...` в демотурнире.

После остановки сервера можно остановить базу:

```powershell
docker compose -p sapientum-demo -f infra/compose.dev.yaml stop
```

Полный сброс **всех данных демостенда** (сначала останови сервер):

```powershell
docker compose -p sapientum-demo -f infra/compose.dev.yaml down -v
npm run dev
```

## Границы локального режима

Хост слушает только loopback. Известные пароли и HTTP-cookie `sapientum_demo_refresh` предназначены для этого режима. Cookie имеет HttpOnly/SameSite=Strict; Secure отсутствует только из-за локального HTTP. Production-контракт описан в [sessions.md](sessions.md). Все мутации проверяют Origin и CSRF; principal создаётся сервером. Пароли демоаккаунтов хранятся как scrypt-хэши с солью. Каталоги демоаккаунтов и демотурнира изолированы от рабочих данных. Этот запуск не заменяет production-сервер и управление реальными аккаунтами и турнирами.
