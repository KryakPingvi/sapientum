# Архитектурные решения

Журнал решений по задачам проекта: что выбрано, почему и какие тесты это закрепляют. Поведение модулей и HTTP-контракты описаны в `docs/<модуль>.md`.

Каждой задаче из issues соответствует один файл. Он входит в тот же PR, что и код задачи.

| Файл                       | Issue                 | PR  | Код                          |
| -------------------------- | --------------------- | --- | ---------------------------- |
| [01-staff.md](01-staff.md) | #1 Оргкомитет и права | #9  | `apps/api/src/modules/staff` |

## Формат записи

Решения в файле пронумерованы и состоят из одинаковых частей:

- **Контекст**: требования и ограничения, из которых выросло решение.
- **Решение**: что сделано.
- **Обоснование**: почему выбран этот вариант.
- **Альтернативы**: рассмотренные варианты и их недостатки, если они были.
- **Последствия**: что решение меняет для других частей системы, если это не очевидно.
- **Реализация**: файлы с кодом.
- **Проверка**: тесты, которые падают при нарушении решения. Тесты лежат в `apps/api/tests`, названия приведены дословно.

Пометка **«Решили сами»** отмечает решения, для которых в требованиях нет ответа. На доске такие места отмечены так же.

## Источники требований

- Доска ивент-шторминга `sapientum.drawio` в корне репозитория. Раздел доски указан в начале каждого файла.
- Демонстрация платформы sapientum.ru заказчиком и ответы на вопросы (сентябрь 2026).
- Положение о турнире и страницы sapientum.ru: правила игр, списки команд.
