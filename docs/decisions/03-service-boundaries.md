# Границы сервисов и согласованность

Решение по ревью PR #10 заменяет прежнее утверждение, что выделение любого модуля требует только замены infrastructure/http.

| Сервис        | Собственные данные                                 |
| ------------- | -------------------------------------------------- |
| Турнир        | Турнир и регистрация, оргкомитет и журнал, команды |
| Идентификация | Аккаунты, пароли, сессии, refresh                  |

Staff и teams — модули одного сервиса турнира. Их SQL-транзакция является намеренной границей согласованности. SQL-клиент передаётся только адаптерам этого владельца. Сервис идентификации не получает доступ к его таблицам и наоборот. Аккаунт проверяется сетевым каталогом, без распределённого коммита с удалением аккаунта; ID аккаунтов не переиспользуются. Блокировка/существование аккаунта также проверяется при аутентификации.

## Подтверждение и отзыв роли

Проверка права подтверждения удерживает shared advisory-lock турнира до коммита. Подтверждения разных команд выполняются параллельно. Смена ролей и исключение берут exclusive-lock того же ключа и ждут уже допущенные операции. Условный UPDATE защищает от двойного подтверждения одной команды. Регистрация и заявки принадлежат той же БД; чтение регистрации с FOR SHARE не допускает закрытия посреди подачи.

Отзыв роли определяется коммитом внутри одного сервиса. Если staff когда-либо будет выделен отдельно, потребуется новый протокол допуска/завершения действий либо явно более слабая согласованность. Простая замена проверки права сетевым вызовом текущую гарантию не сохраняет. Сейчас такое выделение не выбрано.

Проверка сессии по сети предшествует предметной транзакции. Logout запрещает новые проверки, не отменяя уже допущенное действие. При отказе/таймауте идентификации защищённое действие не выполняется. Роли остаются в сервисе турнира.

## Масштабирование и доказательства

Реплики сервиса турнира используют общую собственную БД. Блокировки PostgreSQL действуют между процессами. Идентификация развёртывается отдельно со своей БД; её репликам нужен общий ключ JWT. Независимые единицы развёртывания — эти два сервиса, а не каждый каталог исходников.

PR #10 содержит модули сервиса турнира и конкурентные проверки совместимых допусков и исключительного отзыва. Сам по себе он не доказывает работающую микросервисную систему. Исполняемый стенд с отдельными процессами, проверкой отказов и измерением HTTP-нагрузки относится к зависимому PR #11. Для сдачи архитектуры предъявляются оба PR и результат запуска. Нагрузка на приём фотографий потребует отдельного измерения после реализации этого сценария.

## Публичные данные и покрытие

PublicTeamDto содержит только id, name, organization, status. ФИО, идентификаторы руководителя и автора подтверждения не публикуются. GET возвращает items и nextCursor, сортирует по неизменяемому уникальному id и читает не более limit + 1 строк. По умолчанию limit=50, максимум 100. Курсор — ID последней строки. Это обход текущего списка, а не snapshot; при смене фильтра нужно начинать заново.

CI требует 100% строк, функций, ветвлений и statements через check-coverage в c8. Недостаточное покрытие завершает команду ненулевым кодом. Содержательные сценарии остаются важнее самого числа.
