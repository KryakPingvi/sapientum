# Воспроизводимая проверка HTTP-нагрузки

Команда `npm run dev:process-check` после проверок корректности выполняет серию с одной и двумя репликами турнира. Базы должны быть запущены, HTTP-порты 3000/3001/3002 — свободны. Скрипт запускает и завершает процессы сам. Для уже работающего стенда: `npm run dev:load`; по умолчанию он использует одну реплику 3000.

Настройки: `LOAD_COUNT` (1–1000, по умолчанию 30), `LOAD_CONCURRENCY` (1–50, по умолчанию 6), `LOAD_URLS` (разделённые запятыми loopback URL на 3000/3002). Публичные внешние адреса инструмент не принимает. Перед измерением создаются команды с уникальными названиями; в измеряемую фазу входят только подтверждения. Они включают сетевую проверку сессии, транзакцию турнира и запись подтверждения. Скрипт выводит число ошибок, длительность, requestsPerSecond и p50/p95; при ошибках завершается ненулевым кодом. Созданные команды сохраняются в демобазе.

## Локальный прогон 23 ноября 2026

Windows, Node 22.19, Docker Desktop, PostgreSQL 16; все процессы и контейнеры на одном компьютере. По 30 запросов, параллелизм 6, одна идентификация и одна БД турнира в обеих сериях.

| Реплики турнира | Ошибки | Время, мс | Запросов/с | p50, мс | p95, мс |
| --------------- | ------ | --------- | ---------- | ------- | ------- |
| 1               | 0      | 335       | 89.45      | 41.15   | 183.31  |
| 2               | 0      | 245       | 122.24     | 43.03   | 73.55   |

Это один короткий локальный прогон, без прогрева и повторных серий. Он показывает рабочее распределение запросов между процессами и отсутствие ошибок в этой серии; не устанавливает SLA, предельную пропускную способность или универсальный выигрыш от второй реплики. Сравнение включает влияние кэшей и порядка серий. Для обоснования production-мощностей нужны длительные повторные измерения, профиль оборудования, размеры данных и отдельный сценарий загрузки/обработки фотографий. Shared-блокировки также проверяются содержательным конкурентным тестом, а не только этими цифрами.
